# Аудит общей Rust-ветки NeoTavern

Дата: 2026-10-04. Срез: `1b407fc980c13651c023c76c476db15afcbd3d6e`, ветка `pr-m7-etap6-slices`, с тремя исходными незакоммиченными изменениями. Аудит не изменяет продуктовый код, API, схемы данных или утверждённый стек.

Основной вывод: нестабильность объясняется несколькими общими нарушениями инвариантов. Исправление отдельных отступов, добавление новых fallback и расширение FakeWire не устранят проблемы владения состоянием, выбора конфигурации, выполнения команд и платформенного ввода. Подтверждены реальные ошибки на пути к durable-состоянию, а не только расхождения снимков.

## Общие причины

### 1. Durable-состояние, локальная модель и визуальное представление расходятся

Kernel хранит продуктовые сущности, но ChatSession создаёт собственные значения по умолчанию и частично подменяет прочитанные данные. Сохранённый черновик после открытия чата недоступен (UI-04); язык и prompt settings перезаписываются (UI-06); редактор карточки показывает синтетические поля и сохраняет лишь часть (UI-02). Внешне работающий элемент не доказывает существование полного цикла «изменить → сохранить → перезапустить → прочитать».

Исправление причины: явная гидратация из канонического DTO, отделение UI default от durable value, полный read/write roundtrip для каждого редактируемого поля. Не добавлять очередную копию продуктового состояния в presentation.

### 2. Видимые настройки и команды не определяют фактическое выполнение

Provider selection не попадает в `generation.start` (UI-01). На стороне Kernel adapter выбирается по provider id, а secret отдельно по конфигурации; после перезапуска два профиля одного провайдера дают endpoint одного и ключ другого (KR-02). Prompt plan может сообщать `overBudget=true`, однако реальный запрос всё равно отправляется (KR-13). Изображение контекстного бюджета рассчитывается из видимых строк и констант (UI-09).

Исправление причины: единственный разрешённый путь получения согласованных adapter/model/secret и окончательный budget gate непосредственно перед каждым запросом. UI должен отображать результат этого пути, а не собственную приблизительную трактовку.

### 3. Повтор, завершение и восстановление операций не образуют единую state machine

JNI увеличивает response buffer повторным выполнением уже совершённой мутации: одна команда создаёт два сообщения (KR-04). Стандартный SSE heartbeat ошибочно завершает генерацию (KR-14). Блокирующий provider I/O задерживает общий writer и контроль deadline (KR-11). Быстрый запуск после crash сохраняет «живую» lease старого процесса, которую больше никто не восстанавливает (KR-06).

Исправление причины: повтор выдачи результата без повторного dispatch, однозначные состояния stream/data/EOF/error, cancellation и абсолютный deadline вне блокирующего ожидания, восстановление lease с учётом владельца процесса. Android должен потреблять эту же state machine, без отдельного фиксированного числа poll (PL-04).

### 4. Общий renderer не гарантирует общего поведения приложения

Desktop и Android имеют разные document lifetime, paint paths, input bridges, stream driving и host effects. Фокус, selection, composition, клавиатурные команды и доступность не составляют полноценную общую модель (PL-01/03/04/06). Blueprint переключается на legacy RSX для ряда взаимодействий; непрерывность фокуса и scroll anchor текущими golden-проверками не доказана.

Исправление причины: сначала определить единый контракт ввода, focus owner, scroll anchor и host effects; затем проверять каждый адаптер на одинаковой последовательности событий. Сохранить отдельные platform APIs, но прекратить дублировать продуктовые решения внутри них.

### 5. Перевод design contract содержит собственную семантику и исключения

CSS preprocessing неправильно вычисляет вычитание: `calc(44px - 24px)` становится `68px` (UI-05). Это одна общая причина геометрических ошибок, затрагивающая действительный stylesheet. Наличие compositor glass nodes не означает исполнение glass-pass в текущем host path (PL-L01). Legacy/Blueprint golden сравнивает две нативные реализации, а не React и Rust.

Исправление причины: проверять сохранение смысла CSS преобразованием, определить поддерживаемое подмножество и явно сигнализировать неподдерживаемое. Стабильные slots, rendered geometry и hit-test должны проверяться совместно. Новые координатные поправки и независимые таблицы размеров не заменяют этот контракт.

### 6. Тестовые двойники и старые PASS-записи скрывают границы доказательств

FakeWire выдаёт неполные cursor semantics; загрузка первых 50 сущностей выглядит достаточной, пока настоящий Kernel не содержит 55 (UI-03). Старые формулировки «FIXED/PASS» не соответствуют автоматически текущей ветке: свежие root tests, formatting и contract codegen имеют красные результаты. Проверки React не доказывают нативную accessibility; host-side Android compilation не доказывает Gboard, TalkBack или SurfaceView lifecycle.

Исправление причины: поведенческий conformance для FakeWire и настоящего Kernel, отдельная матрица capabilities для каждой реально поставляемой комбинации shell/backend, привязка PASS к commit, бинарнику, данным и сценарию.

## Границы заключения

`RUNTIME_CONFIRMED` означает наблюдение на настоящем локальном пути с сохранённым доказательством; `STATIC_CONFIRMED` — доступный ошибочный путь в исходниках без полного runtime прогона; `RISK` — гипотеза; `DOCUMENTED_LIMITATION` — явно принятое ограничение. `NOT_RUN` не является PASS или дефектом само по себе.

Android-устройств нет. Физические Gboard, TalkBack, SurfaceView, GPU/performance прогоны не выполнены. macOS/Linux и установленный packaged Tauri не получили runtime PASS. Проверка платформ в полном объёме остаётся незавершённой. Успешная сборка Windows probe и успешные узкие тесты не снимают эти ограничения.
