The public documentation site is a Docusaurus project in `apps/docs`. This page
explains its layout and how to add or update pages.

## Layout

- English source pages live in `apps/docs/docs/`, one markdown file per page,
  organized into the same directories the sidebar shows.
- Translations live in
  `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/`, mirroring
  the English tree one file per page; see [Translations](./translations).
- The SDK reference under `apps/docs/docs/api/` is generated and gitignored; do
  not edit it by hand.

## Adding a Page

1. Create the markdown file in the directory that matches where the page should
   appear.
2. Add front matter with `title`, `description`, and `sidebar_position`:

   ```yaml
   ---
   title: Page Title
   description: One sentence describing the page.
   sidebar_position: 3
   ---
   ```

3. Open with a one-sentence summary of what the page covers.
4. Use `##` and `###` for sections; the front matter `title` provides the
   single H1.
5. If you add a new directory, create a `_category_.json` in it:

   ```json
   { "label": "Category Label", "position": 2 }
   ```

`sidebar_position` orders pages within their directory; the Overview page is 1.
Content-sidebar sections are autogenerated from the directory structure.

## MDX Limits

Pages are plain Markdown plus Docusaurus admonitions only:

```md
:::note
Text inside the admonition.
:::
```

No `import` statements, no custom JSX components, no tabs, and no raw HTML.
Every page must stay copyable verbatim into any of the eight translation
locales. Code samples use fenced blocks with a language tag.

## SDK Reference

The SDK reference is generated by TypeDoc from each package's entry point:

- `packages/plugin-sdk/src/index.ts` -> `apps/docs/docs/api/plugin-sdk/`
- `packages/theme-sdk/src/index.ts` -> `apps/docs/docs/api/theme-sdk/`
- `packages/provider-sdk/src/index.ts` -> `apps/docs/docs/api/provider-sdk/`
- `packages/contracts/src/index.ts` -> `apps/docs/docs/api/contracts/`

The reference regenerates on every site build, so edits to generated pages are
lost. To fix a reference page, fix the TSDoc in the package source instead. The
overview at `apps/docs/docs/api/index.md` is hand-written and stays committed.

## Running the Site

```bash
pnpm docs:site        # local dev server with hot reload
pnpm docs:site:build  # production build: all locales plus the SDK reference
```

The production build is the gate — broken links and broken markdown links fail
it — so run it before pushing content changes.

## Link Rules

Internal links must point at pages that exist in the site. Prefer absolute site
paths from the home page (`/getting-started/`) and relative paths from deeper
pages (`../developers/` from a page under `contributing/`). External links are
limited to the Docusaurus documentation and the NeoTavern repository.

## Internal Developer Docs

The repository also keeps internal developer documentation in `docs/` at the
repo root, validated by `pnpm docs:check` and `pnpm docs:build`. That is a
separate set of documents from this public site; do not confuse the two trees.
