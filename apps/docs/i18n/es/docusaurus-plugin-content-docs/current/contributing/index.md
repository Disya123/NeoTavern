NeoTavern es un proyecto abierto, y las contribuciones de todo tipo son
bienvenidas: informes de errores, solicitudes de funciones, código,
documentación y traducciones.

## Formas de Contribuir

- **Informar errores y solicitar funciones.** Abre un issue en GitHub con la
  versión, tu sistema operativo y los pasos para reproducirlo:
  [https://github.com/Disya123/NeoTavern/issues](https://github.com/Disya123/NeoTavern/issues)
- **Escribir código.** Elige un issue, comenta en él y abre un pull request.
  Mantén los cambios pequeños y sigue las [Pautas de código](contributing/code-guidelines).
- **Mejorar la documentación.** El sitio público vive en `apps/docs`; consulta
  [Sitio de documentación](contributing/docs-site).
- **Traducir.** Ayuda con uno de los ocho locales o propón uno nuevo; consulta
  [Traducciones](contributing/translations).

## Código de Conducta

Trata a los demás contribuyentes con respeto. Sé constructivo en las
revisiones y los issues, asume la buena fe y mantén la discusión centrada en
el trabajo. El [AGENTS.md](https://github.com/Disya123/NeoTavern/blob/main/AGENTS.md)
del repositorio es la descripción autorizada de cómo se construye el
proyecto y cómo se completan las tareas; léelo antes de tu primer cambio.

## Antes de Empezar

- Lee primero la [Configuración de desarrollo](contributing/development-setup) y las
  [Pautas de código](contributing/code-guidelines), además del archivo AGENTS.md
  enlazado arriba.
- Busca un issue existente que cubra lo que quieres hacer, y comenta antes
  de empezar un trabajo grande para que los mantenedores puedan dar
  comentarios tempranos.
- Mantén los pull requests enfocados: un cambio lógico por PR, con pruebas y
  documentación incluidas.

## Qué Ocurre Después de Enviar

Los mantenedores revisan el cambio y CI ejecuta las puertas de calidad —
lint, typecheck y pruebas. Una vez que todo está en verde, el pull request
se fusiona y los cambios visibles para el usuario llegan al registro de
cambios.
