このページでは、NeoTavern のアップデートがどのように配信されるか、アップグレード中にデータに何が起こるか、変更点をどこで確認できるかを説明します。

## アップデートの仕組み

NeoTavern はコアアプリ、プラグイン、テーマをそれぞれ独立した単位として扱い、それぞれが個別に更新されます:

- **コアのアップデート** はアプリケーション自体を置き換えますが、データディレクトリには触れません。
- **プラグインとテーマのアップデート** はアプリ内のそれぞれのマネージャーを通じて行われ、あなたの確認なしに自動で有効化されることはありません。
- すべてのインストールはアトミックです: 新しいバージョンが 1 つのステップで古いバージョンを置き換え、前のバージョンは失敗したアップデートをロールバックできるよう保持されます。
- パッケージの整合性はチェックサムで検証され、公式カタログではさらに署名が追加される場合があります。

アップデートに Git、npm、ターミナルは一切不要です。通常どおりインストールしたなら、アップデートも同じ方法で行います。

## アップグレード中のデータの安全性

- アップデートがユーザーファイルを直接変更することはありません: キャラクター、チャット、ロアブック、ペルソナ、設定はインストーラーから触れられません。
- アップデートにデータベーススキーマのマイグレーションが含まれる場合、マイグレーション実行前にバックアップが作成され、マイグレーションはトランザクション的かつ冪等です。
- SQLite データベースは WAL モードで動作するため、マイグレーションやアップグレード中もアプリは使用可能で、書き込みの耐久性は維持されます。
- プラグインやテーマのアップデートが失敗した場合、アプリは中途半端にインストールされたパッケージを残す代わりに、前のバージョンを動作させ続けます。

## 変更点の確認

[変更履歴](https://github.com/Disya123/NeoTavern/blob/main/CHANGELOG.md) にはすべての変更がその影響とともに記載されています。アップグレード前に最新のエントリをざっと確認してください: 破壊的変更にはマイグレーションガイドが付属し、まだ実験的または計画中の機能は明示的にマークされています。

## プラグインとテーマのアップデート

Plugins セクションと Themes セクションを開きます。インストール済みの各項目には、バージョン、ステータス、アップデートの有無が表示されます。アップデートが新しい権限を要求する場合、適用前に改めて明示的な同意が求められます — アップデートによって権限が黙って拡張されることはありません。

## ロールバック

コアのアップデート中は前のバージョンが保持されるため、新しいリリースに問題があれば再インストールできます。データディレクトリは後方互換で読み取れ、リスクのあるマイグレーションの前に作成されたバックアップを使えば、UI から既知の正常状態を復元できます。[データとバックアップ](../user-guide/data-and-backups) を参照してください。
