NeoTavern のコードコントリビューションは共有ルールのセットに従います: 厳格な TypeScript、明示的なエラーコントラクト、変更の一部としてのドキュメント、測定可能なパフォーマンス目標です。

## TypeScript

- すべてのコードで厳格モードが有効です。維持してください。
- 正当性のない `any`、`@ts-ignore`、非 null アサーション、`as unknown as` キャストは禁止されています。
- システム境界 — パース、リクエスト、ファイル、プラグイン入力 — では `unknown` を使用し、データを信頼する前に明示的に検証してください。
- 公開インターフェースはエクスポートされた型を公開します。バックエンドとフロントエンドの型を手で重複させないでください: 共有 API 型は `packages/contracts` にあり、そこからインポートされます。
- 全体で ESM を使用してください。
- 大きなステートフル関数よりも、明示的な入力と出力を持つ小さな関数を優先してください。

## API エラー

すべての API エラーは安定したマシン可読なエンベロープを使用します:

```json
{
  "code": "CHARACTER_NOT_FOUND",
  "params": { "characterId": "0193..." },
  "traceId": "01J4..."
}
```

- `code` は安定したマシン可読なエラー識別子です — 出荷したら変更しないでください。
- `params` はクライアントやプラグインが対応できる構造化コンテキストを運びます。
- `traceId` はエラーをサーバーログと関連付けます。
- ユーザー向けテキストはバックエンドで構成されません: フロントエンドがコードとパラメータを UI テキストにローカライズします。

## ドキュメントは実装の一部

ドキュメントは実装の一部であり、コードの後に来る尻尾ではありません。ユーザーまたは開発者の動作に影響する変更は、同じ変更で `docs/` の関連ファイルを更新します。これは以下で必須です:

- アーキテクチャとパッケージ境界;
- REST API、SSE、WebSocket、コントラクトスキーマ;
- プラグイン SDK、テーマ SDK、レガシー互換レイヤー;
- 権限、サンドボックス化、セキュリティモデル;
- SQLite スキーマ、マイグレーション、バックアップ、復元;
- インポート、エクスポート、ファイル、サムネイルキャッシュ;
- プロンプトパイプライン、インストラクトフォーマット、トークナイゼーション、コンテキストシフティング;
- プロバイダーアダプター;
- デスクトップのパッケージング、Tauri サイドカー、PWA、アップデート;
- ユーザー設定、i18n、アクセシビリティ;
- 破壊的変更、非推奨、マイグレーションガイド。

追加ルール:

- 新しい `app` または `package` には、目的、公開エントリポイント、依存関係、開発コマンド、制約をカバーする `README.md` が同梱されます。
- 公開 TypeScript エクスポートと SDK 拡張ポイントは、名前だけではコントラクトを説明できない場合に TSDoc を取得します。
- ユーザーに見える変更は `CHANGELOG.md` に追加され、破壊的変更はマイグレーションガイドも取得します。
- 未実装の機能を実装済みとして文書化しないでください — 「実験的」または「計画中」とマークしてください。
- コントラクトごとに 1 つの情報源を維持し、それにリンクしてください。同じコントラクトを複数の場所にコピーしないでください。

## i18n

- UI コードにハードコードされたユーザー向け文字列はありません。すべての文字列は i18next 名前空間を通ります。
- 複数形、日付、数字、単位は文字列連結ではなく `Intl` でフォーマットしてください。
- ページリロードなしで言語を切り替え、`<html>` の `lang` と `dir` を更新してください。
- RTL レイアウトをサポートしてください。
- プラグインとテーマは分離された名前空間を使用するため、アプリと衝突しません。
- バックエンドはエラーコードを返し、フロントエンドがローカライズします。
- 新しい画面に疑似ロケールチェックを追加し、長い翻訳でインターフェースを検証してください。

## パフォーマンス目標

明示的な決定なしにこれらの目標を後退させないでください:

| 目標                                                | 予算       |
| --------------------------------------------------- | ---------- |
| 起動から UI 準備完了まで（基準 PC）                 | 4 秒       |
| バックエンドのアイドルメモリ                        | 180 MB     |
| 100,000 キャラクターの最初のページ                  | 300 ms     |
| 10,000 メッセージのチャットを最新メッセージまで開く | 700 ms     |
| ストリーミング UI の更新                            | 毎秒 30 回 |
| 初期フロントエンドバンドル（gzip、遅延チャンク前）  | 2 MB       |

最適化の前後で測定してください。無効化戦略のないキャッシュを追加しないでください。

## テスト

すべての変更は適切なレベルでテストを追加します: Vitest ユニットテスト、Fastify `inject()` 統合テスト、Playwright エンドツーエンドテスト、テーマとシェルレイアウトのビジュアルリグレッション、アクセシビリティテスト、マイグレーションテスト、プラグインコントラクトテスト、レガシー互換スイートです。エラーと破損した入力、リクエストのキャンセル、再インポート、マイグレーションとロールバック、バックアップの復元、キャッシュのクリーンアップ、プラグインの無効化、セーフモード、大規模カタログと長いチャット、トークン予算境界でのコンテキストシフティング、インストラクトフォーマットのレンダリング、サムネイルの生成と無効化をカバーしてください。

## 完了の定義

プッシュする前に: `pnpm format`、警告ゼロの `pnpm lint`、`pnpm typecheck`、`pnpm test`、UI 変更には `pnpm test:e2e` を実行してください。関連するドキュメント、例、マイグレーションガイドが更新され、ドキュメントリンクが解決することを確認してください。
