NeoTavern — открытый проект, и вклад любого рода приветствуется: сообщения об
ошибках, запросы функций, код, документация и переводы.

## Способы внести вклад

- **Сообщайте об ошибках и запрашивайте функции.** Откройте issue на GitHub
  с версией, вашей ОС и шагами воспроизведения:
  [https://github.com/Disya123/NeoTavern/issues](https://github.com/Disya123/NeoTavern/issues)
- **Пишите код.** Выберите issue, прокомментируйте его и откройте pull
  request. Держите изменения небольшими и следуйте
  [Правилам написания кода](contributing/code-guidelines).
- **Улучшайте документацию.** Публичный сайт живёт в `apps/docs`; см.
  [Сайт документации](contributing/docs-site).
- **Переводите.** Помогите с одной из восьми локалей или предложите новую;
  см. [Переводы](contributing/translations).

## Кодекс поведения

Относитесь к другим участникам с уважением. Будьте конструктивны в
ревью и issue, исходите из добрых намерений и держите обсуждение
сфокусированным на работе. Файл
[AGENTS.md](https://github.com/Disya123/NeoTavern/blob/main/AGENTS.md)
репозитория — авторитетное описание того, как строится проект и как
выполняются задачи; прочитайте его перед первым изменением.

## Прежде чем начать

- Сначала прочитайте [Настройку окружения разработчика](contributing/development-setup)
  и [Правила написания кода](contributing/code-guidelines), а также упомянутый выше
  AGENTS.md.
- Поищите существующее issue по вашей теме и прокомментируйте его перед
  началом большой работы, чтобы мейнтейнеры могли дать раннюю обратную связь.
- Держите pull request сфокусированным: одна логическая правка на PR, с
  тестами и документацией.

## Что происходит после отправки

Мейнтейнеры ревьюят изменение, а CI прогоняет гейты качества — lint,
typecheck и тесты. Когда всё зелёное, pull request сливается, а
пользовательские изменения попадают в журнал изменений.
