Публичный сайт документации — это проект Docusaurus в `apps/docs`. На этой
странице объясняется его структура и то, как добавлять или обновлять
страницы.

## Структура

- Исходные страницы на английском живут в `apps/docs/docs/`, по одному файлу
  markdown на страницу, организованные в те же каталоги, которые показывает
  сайдбар.
- Переводы живут в
  `apps/docs/i18n/<locale>/docusaurus-plugin-content-docs/current/`,
  зеркалируя английское дерево по одному файлу на страницу; см.
  [Переводы](./translations).
- Справочник SDK в `apps/docs/docs/api/` генерируется и в gitignore; не
  редактируйте его вручную.

## Добавление страницы

1. Создайте файл markdown в каталоге, соответствующем месту страницы.
2. Добавьте front matter с `title`, `description` и `sidebar_position`:

   ```yaml
   ---
   title: Page Title
   description: One sentence describing the page.
   sidebar_position: 3
   ---
   ```

3. Откройте страницу однопредложеннным резюме того, что она охватывает.
4. Используйте `##` и `###` для разделов; `title` из front matter
   предоставляет единственный H1.
5. Если вы добавляете новый каталог, создайте в нём `_category_.json`:

   ```json
   { "label": "Category Label", "position": 2 }
   ```

`sidebar_position` упорядочивает страницы внутри их каталога; страница обзора
— 1. Разделы сайдбара контента автогенерируются из структуры каталогов.

## Ограничения MDX

Страницы — это только обычный Markdown плюс адмоншены Docusaurus:

```md
:::note
Text inside the admonition.
:::
```

Никаких `import`, никаких пользовательских JSX-компонентов, никаких вкладок
и никакого сырого HTML. Каждая страница должна оставаться копируемой
дословно во все восемь локалей перевода. Примеры кода используют ограждённые
блоки с тегом языка.

## Справочник SDK

Справочник SDK генерируется TypeDoc из точки входа каждого пакета:

- `packages/plugin-sdk/src/index.ts` -> `apps/docs/docs/api/plugin-sdk/`
- `packages/theme-sdk/src/index.ts` -> `apps/docs/docs/api/theme-sdk/`
- `packages/provider-sdk/src/index.ts` -> `apps/docs/docs/api/provider-sdk/`
- `packages/contracts/src/index.ts` -> `apps/docs/docs/api/contracts/`

Справочник пересоздаётся при каждой сборке сайта, поэтому правки
сгенерированных страниц теряются. Чтобы исправить страницу справочника,
исправьте TSDoc в исходнике пакета. Обзор в `apps/docs/docs/api/index.md`
написан вручную и остаётся в репозитории.

## Запуск сайта

```bash
pnpm docs:site        # local dev server with hot reload
pnpm docs:site:build  # production build: all locales plus the SDK reference
```

Продакшн-сборка — это гейт: сломанные ссылки и сломанные markdown-ссылки
валит её, — поэтому запускайте её перед пушем изменений контента.

## Правила ссылок

Внутренние ссылки должны указывать на существующие страницы сайта.
Предпочитайте абсолютные пути сайта с домашней страницы (`/getting-started/`)
и относительные пути с более глубоких страниц (`../developers/` со страницы
в `contributing/`). Внешние ссылки ограничены документацией Docusaurus и
репозиторием NeoTavern.

## Внутренняя документация разработчика

Репозиторий также хранит внутреннюю документацию разработчика в `docs/` в
корне репозитория, проверяемую через `pnpm docs:check` и `pnpm docs:build`.
Это отдельный набор документов от этого публичного сайта; не путайте два
дерева.
