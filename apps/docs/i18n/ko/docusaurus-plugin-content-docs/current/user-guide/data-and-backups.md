이 페이지는 데이터가 어디에 저장되는지, 데이터 디렉터리에 무엇이
들어 있는지, 라이브러리를 내보내고 가져오고 백업하는 방법을
설명합니다.

## 데이터 디렉터리

모든 사용자 데이터는 첫 실행 시 생성되는 하나의 데이터 디렉터리에
있습니다. 정확한 위치는 설정 → 데이터에 표시되며, `NEOTA_DATA_DIR` 환경
변수로 서버를 다른 위치에 지정할 수 있습니다. 구조는 다음과 같습니다.

- `app.db` — SQLite 데이터베이스: 캐릭터, 채팅, 메시지, 로어북, 메모리
  항목, 페르소나, 프리셋, 설정. WAL 모드, 외래 키 활성화, 캐릭터·채팅·
  메시지 전체 텍스트 검색으로 실행됩니다.
- `files/` — 원본 사용자 파일: 아바타, 배경, 첨부 파일, 오디오, 생성된
  이미지. 파생 데이터가 아닙니다.
- `cache/` — 재생성 가능한 데이터: 썸네일, 토크나이저 데이터, 플러그인
  다운로드. 캐시를 지워도 원본은 건드리지 않습니다.
- `backups/` — UI에서 만드는 백업 아카이브.
- `logs/` — 비식별화된 서버 로그.
- `plugins/` 및 `themes/` — 설치된 패키지로, 각각 자체 디렉터리에
  격리됩니다.

## 저장되는 것

캐릭터와 카드, 전체 메시지 기록과 스와이프 변형이 있는 채팅, 로어북,
메모리 항목, 페르소나, 생성 프리셋, 연결 프로필, 테마, 플러그인, 설정이
저장됩니다. API 키는 암호화된 키 관리자에 로컬로 저장되며 로그, 브라우저
저장소, 진단 내보내기에 기록되지 않습니다.

## 내보내기와 가져오기

- **캐릭터 카드**는 PNG 또는 JSON으로 내보내지고, 채팅은 보관하거나
  다른 기기로 옮길 수 있는 아카이브로 내보내집니다.
  [캐릭터](characters)를 참조하세요.
- **SillyTavern 마이그레이션**은 설정 → 데이터에 있습니다. 전체 데이터
  백업 ZIP을 선택하면 앱이 먼저 읽기 전용 분석을 실행해 캐릭터, 채팅,
  페르소나, 로어북, 프리셋 범주별로 객체, 중첩 레코드, 손상, 크기,
  충돌을 보고합니다. 보고서를 검토하고 확인하기 전에는 아무것도
  기록되지 않습니다. 그런 다음 범주와 명시적 충돌 정책(기존 항목 유지,
  복사본 생성, 안전하게 병합, 아카이브에서 교체)을 선택합니다. 비밀,
  플러그인, 테마, 지원되지 않는 범주는 건너뜀으로 표시되며, 가져오기를
  반복해도 중복이 생기지 않습니다.

## 백업

백업은 설정 → 데이터에서 전적으로 UI로 생성하고 복원합니다.

- 언제든 **만들기**를 실행할 수 있으며, 백업 생성이 데이터 읽기를
  막지 않습니다.
- 백업 화면에는 날짜, 크기, 스키마 버전, 소스, 상태가 표시됩니다.
- **복원**은 확인을 요구하고, 먼저 현재 상태의 보호용 백업을 만든
  다음, 이후 앱을 다시 시작해야 한다고 알려줍니다.
- 복원은 무결성 검증 후에만 성공으로 보고됩니다. 실패하면 앱은 보호용
  복사본으로 자동 복귀를 제안합니다.

위험한 스키마 마이그레이션 전에는 앱이 스스로 백업을 만듭니다. WAL
데이터베이스와 결합하면 업그레이드나 복원에 항상 알려진 정상
폴백이 있습니다. [업그레이드](../getting-started/upgrading)를
참조하세요.
