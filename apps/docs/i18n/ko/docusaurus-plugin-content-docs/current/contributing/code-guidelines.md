NeoTavern 코드 기여는 공유된 규칙 집합을 따릅니다. 엄격한
TypeScript, 명시적 오류 계약, 구현의 일부인 문서, 측정 가능한 성능
목표입니다.

## TypeScript

- 모든 코드에서 엄격 모드가 활성화되어 있습니다. 계속 켜 두세요.
- 정당화되지 않은 `any`, `@ts-ignore`, non-null 단언, `as unknown as`
  캐스트는 금지됩니다.
- 시스템 경계 — 파싱, 요청, 파일, 플러그인 입력 — 에서는 `unknown`을
  사용하고 데이터를 신뢰하기 전에 명시적으로 검증하세요.
- 공개 인터페이스는 내보낸 타입을 노출합니다. 백엔드와 프론트엔드
  타입을 손으로 중복하지 마세요. 공유 API 타입은 `packages/contracts`에
  있으며 거기서 가져옵니다.
- 전체에서 ESM을 사용하세요.
- 크고 상태가 있는 함수보다 명시적 입력과 출력이 있는 작은 함수를
  선호하세요.

## API 오류

모든 API 오류는 안정적이고 기계가 읽을 수 있는 봉투를 사용합니다.

```json
{
  "code": "CHARACTER_NOT_FOUND",
  "params": { "characterId": "0193..." },
  "traceId": "01J4..."
}
```

- `code`는 안정적이고 기계가 읽을 수 있는 오류 식별자입니다. 일단
  출시되면 바꾸지 마세요.
- `params`는 클라이언트나 플러그인이 조치할 수 있는 구조화된
  컨텍스트를 담습니다.
- `traceId`는 오류를 서버 로그와 연결합니다.
- 사용자 대상 텍스트는 백엔드에서 절대 작성하지 않습니다. 프론트엔드가
  코드와 params를 UI 텍스트로 지역화합니다.

## 문서는 구현의 일부

문서는 코드 뒤에 따라오는 꼬리가 아니라 구현의 일부입니다. 사용자나
개발자 동작에 영향을 주는 변경은 같은 변경에서 `docs/`의 관련 파일을
업데이트합니다. 다음에 필수입니다.

- 아키텍처와 패키지 경계;
- REST API, SSE, WebSocket, 계약 스키마;
- Plugin SDK, Theme SDK, 레거시 호환 계층;
- 권한, 샌드박싱, 보안 모델;
- SQLite 스키마, 마이그레이션, 백업, 복원;
- 가져오기, 내보내기, 파일, 썸네일 캐시;
- 프롬프트 파이프라인, 인스트럭트 포맷, 토큰화, 컨텍스트 시프팅;
- 프로바이더 어댑터;
- 데스크톱 패키징, Tauri 사이드카, PWA, 업데이트;
- 사용자 설정, i18n, 접근성;
- 호환성이 깨지는 변경, 사용 중단, 마이그레이션 가이드.

추가 규칙:

- 모든 새 `app` 또는 `package`는 목적, 공개 진입점, 의존성, 개발
  명령어, 제약 조건을 다루는 `README.md`를 제공합니다.
- 공개 TypeScript 내보내기와 SDK 확장 지점은 이름만으로 계약을
  설명할 수 없을 때 TSDoc을 받습니다.
- 사용자에게 보이는 변경은 `CHANGELOG.md`에 추가되며, 호환성이 깨지는
  변경은 마이그레이션 가이드도 받습니다.
- 구현되지 않은 기능을 준비된 것으로 문서화하지 마세요. "실험적" 또는
  "계획됨"으로 표시하세요.
- 계약당 하나의 진실 공급원을 유지하고 그것에 연결하세요. 같은 계약을
  여러 곳에 복사하지 마세요.

## i18n

- UI 코드에 하드코딩된 사용자 대상 문자열이 없습니다. 모든 문자열은
  i18next 네임스페이스를 통과합니다.
- 복수형, 날짜, 숫자, 단위는 문자열 연결이 아니라 `Intl`로
  포맷하세요.
- 페이지 새로고침 없이 언어를 전환하고 `<html>`의 `lang`과 `dir`을
  업데이트하세요.
- RTL 레이아웃을 지원하세요.
- 플러그인과 테마는 격리된 네임스페이스를 사용해 앱과 충돌하지 않게
  합니다.
- 백엔드는 오류 코드를 반환하고 프론트엔드가 지역화합니다.
- 새 화면에 의사 로케일 검사를 추가하고 긴 번역으로 인터페이스를
  검증하세요.

## 성능 목표

명시적 결정 없이 다음 목표를 퇴행시키지 마세요.

| 목표                                      | 예산      |
| ----------------------------------------- | --------- |
| 시작부터 준비된 UI까지 (기준 PC)          | 4초       |
| 백엔드 유휴 메모리                        | 180 MB    |
| 캐릭터 100,000명의 첫 페이지              | 300 ms    |
| 10,000메시지 채팅을 최신 메시지로 열기    | 700 ms    |
| 스트리밍 UI 업데이트                      | 초당 30회 |
| 초기 프론트엔드 번들 (gzip, 지연 청크 전) | 2 MB      |

최적화 전후를 측정하세요. 무효화 전략 없이 캐시를 추가하지 마세요.

## 테스트

모든 변경은 적절한 수준의 테스트를 추가합니다. Vitest 단위 테스트,
Fastify `inject()` 통합 테스트, Playwright 엔드투엔드 테스트, 테마와
셸 레이아웃의 시각적 회귀 테스트, 접근성 테스트, 마이그레이션 테스트,
플러그인 계약 테스트, 레거시 호환성 스위트입니다. 오류 및 손상 입력,
요청 취소, 재가져오기, 마이그레이션과 롤백, 백업 복원, 캐시 정리,
플러그인 비활성화, 세이프 모드, 대규모 카탈로그와 긴 채팅, 토큰 예산
경계의 컨텍스트 시프팅, 인스트럭트 포맷 렌더링, 썸네일 생성과 무효화를
다루세요.

## 완료의 정의

푸시 전에: `pnpm format`, 경고 0의 `pnpm lint`, `pnpm typecheck`,
`pnpm test`, UI 변경 시 `pnpm test:e2e`. 관련 문서, 예시, 마이그레이션
가이드가 업데이트되었고 문서 링크가 해석되는지 확인하세요.
