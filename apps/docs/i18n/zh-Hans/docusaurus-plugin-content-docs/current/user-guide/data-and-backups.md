本页说明你的数据存放在哪里、数据目录包含什么，以及如何导出、导入和备份
你的资料库。

## 数据目录

所有用户数据都存放在一个数据目录中，首次运行时创建。其确切位置显示在
设置 → 数据中；你可以使用 `NEOTA_DATA_DIR` 环境变量把服务器指向另一个位置。
布局如下：

- `app.db` —— SQLite 数据库：角色、聊天记录、消息、设定集、记忆条目、
  人设、预设和设置。它以 WAL 模式运行，启用了外键，并为角色、聊天记录
  和消息提供全文搜索。
- `files/` —— 原始用户文件：头像、背景、附件、音频和生成的图像。
  这些绝不是派生数据。
- `cache/` —— 可重新生成的数据：缩略图、分词器数据和插件下载。
  清除缓存绝不会触碰你的原始文件。
- `backups/` —— 你从界面创建的备份归档。
- `logs/` —— 经过脱敏的服务器日志。
- `plugins/` 和 `themes/` —— 已安装的软件包，每个都限制在自己的目录中。

## 存储了什么

角色及其卡片、带完整消息历史和滑动变体的聊天记录、设定集、记忆条目、
人设、生成预设、连接配置文件、主题、插件和你的设置。API 密钥存储在本地
加密密钥管理器中，绝不会写入日志、浏览器存储或诊断导出。

## 导出和导入

- **角色卡**导出为 PNG 或 JSON，聊天记录导出为你可以保存或移动到另一台
  机器的归档。请参阅[角色](characters)。
- **SillyTavern 迁移**位于设置 → 数据中：选择一个完整的数据备份 ZIP，
  应用会先运行一次只读分析，按类别报告对象、嵌套记录、损坏、大小和冲突
  —— 角色、聊天记录、人设、设定集和预设。在你审查报告并确认之前，
  不会写入任何内容。然后你选择类别和一种明确的冲突策略（保留现有、创建副本、
  安全合并或从归档替换）。密钥、插件、主题和不支持的类别会被列为跳过项，
  重复导入绝不会产生重复。

## 备份

备份完全在设置 → 数据中通过界面创建和恢复：

- 随时**创建**备份；创建备份不会阻止你读取数据。
- 备份屏幕显示日期、大小、schema 版本、来源和状态。
- **恢复**会请求确认，首先创建当前状态的一个保护性备份，
  并告知你之后应用必须重启。
- 只有在完整性验证通过后，恢复才会被报告为成功；如果失败，
  应用会自动提供返回保护性副本的选项。

在任何危险的 schema 迁移之前，应用会自动创建备份。结合 WAL 数据库，
这意味着升级或恢复总是有一个已知良好的回退。请参阅
[升级](../getting-started/upgrading)。
