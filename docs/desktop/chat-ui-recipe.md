# Рецепт: правка UI чата без перекомпиляции (M3 + M4 волна 1)

С M2 структура чата — данные: узлы, вложенность, порядок и действия
композера, хедера и ленты сообщений читаются из авторского JSON-документа, а
не из рукописного RSX. С M4 волной 1 **презентация тоже данные**: подписи
кнопок, иконки и токен-стили живут в том же документе. Этот документ — единая
петля «правка → проверка».

## Петля правки

`pnpm ui:dev [document.json] [--w 1100] [--h 760] [--messages 12] [--watch]`
проверяет актуальность release-сборки через Cargo при каждом запуске.
`NEOTA_DESKTOP_BIN` явно выбирает готовый бинарник и отключает эту сборку.
Без пути рабочий документ создаётся в системной временной папке
`neotavern-ui-dev/chat.document.json` только при первом запуске: последующие
запуски сохраняют ваши изменения. Для возврата к шаблону используйте отдельную
копию канонического документа. Параметры размера и количества сообщений можно
ставить до пути; их значения не интерпретируются как имена файлов.

Флаг `--watch` добавляет второй контур правки: изменения `.rs` в
`crates/presentation-*` (после дебаунса 1.5 с) останавливают окно,
пересобирают release-бин и перезапускают его; упавшая сборка оставляет
работать предыдущий бинарник, ручное закрытие окна завершает цикл. Документ
при этом продолжает хот-релодиться в процессе (следующий абзац), так что
правка JSON не требует пересборки, а правка Rust — одного сохранения.

В режиме файлового документа хост проверяет mtime и размер каждые 100 мс
в простое и запрашивает кадр при изменении, даже без клика или ресайза окна.
Неизменённый документ не вызывает перерисовку. Ошибка разбора кэшируется до
следующего изменения файла; исправление или восстановление удалённого файла
автоматически возвращает документ. Встроенный документ не включает опрос.
Изменения с одновременно сохранёнными mtime и размером не обнаруживаются.

0. **Настройте редактор один раз**: VS Code подхватывает схему через
   `.vscode/settings.json` (автодополнение полей, закрытых union'ов действий,
   иконок и токен-паттерна). После изменения схемы выполните `pnpm ui:schema`
   (гейт свежести — `pnpm ui:schema:check`).
1. **Скопируйте** канонический документ в рабочую копию и правьте JSON:
   добавляйте, удаляйте, перемещайте узлы (`nodeId` уникальны), меняйте
   вложенность, действия и презентацию.
2. **Проверьте документ**: `pnpm blueprint:validate my-document.json`.
   Ошибки схемы останавливают (код 1); предупреждения (например, i18n-ключ,
   которого нет в ресурсах) печатаются как `warn:` и не мешают запуску.
3. **Запустите хост со своим документом**:
   `neocompositor-desktop --blueprint <path>` или переменная
   `NEOTA_CHAT_BLUEPRINT_DOC=<path>`. Без них хост уже работает на
   встроенном документе (ADR-0056, этап 1); вернуться к рукописному RSX
   целиком можно флагом `--legacy-chrome` или `NEOTA_LEGACY_CHROME=1`.
   Документ перечитывается при изменении mtime; ошибка разбора печатается в
   stderr один раз, а чат живёт на легаси-фоллбеке до починки. Правки
   подхватываются следующим кадром без перезапуска.
4. **Проверьте структуру**: `--dom-dump <json>` покажет Theme SDK-хуки;
   сравнение с легаси — `cargo test --manifest-path crates/Cargo.toml -p
neotavern-presentation-chat --test compositor_host blueprint_chrome`.
5. **Проверьте пиксели** (после намеренного визуального изменения сначала
   обновите goldens легаси): `pnpm chat:golden` затем `pnpm chat:golden:check`.

## Правила документа

- Структура = документ: id узлов, порядок, вложенность, действия
  (`actions[].id` из реестра wire) читаются оттуда. Неизвестные `nodeId`
  проходят как generic-flow узлы — структурная правка никогда не требует
  одновременной правки кода.
- **Презентация = документ (M4 волна 1).** У узла есть опциональные поля:
  - `label: { text, i18nKey? }` — видимый текст и/или aria; ключ вида
    `chat.send` обязан существовать в ресурсах `packages/i18n`
    (`en.ts`/`ru.ts`), иначе валидатор предупреждает. Текст перекрывает
    только те места, где кнопка уже рисует текст (aria/title/видимый span);
    у икон-only кнопки он меняет лишь aria — новый текст из документа не
    появляется;
  - `icon` — закрытый реестр `UI_ICON_IDS`, зеркалирующий `PHOSPHOR_REGULAR`
    (единственные глифы, которые умеет рисовать нативный рендерер);
  - `styleRefs: [{ property, token }]` — только дизайн-токены
    (`var(--…)`); сырые цвета/размеры схема отвергает. Объявления
    дописываются после встроенного стиля узла и выигрывают каскад.
    Приоритет всегда: документ → встроенная таблица рендерера по node-id.
    Семантический ключ доступности предпочитает `label.i18nKey`.
- Кнопки композера в канонической фикстуре уже несут презентацию данными
  (Send/Settings/Reset/utilities); контекстный триггер с динамическим
  процентом и строки сообщений пока берут значения из таблиц.
- Шаблон строки сообщения — узел `chat-message`; он разворачивается по одному
  экземпляру на сообщение, действия с `parameter: "messageId"`
  привязываются к конкретной строке.
- Презентация, которой ещё нет в документе (классы контейнеров, стили строк,
  геометрия), живёт в таблицах по стабильным `nodeId`: хуки/лейблы —
  `presentation-blueprint/src/v1/chat.rs`, рендер —
  `presentation-dioxus-shell/src/scene_chat.rs`. Новый _интерактивный_ узел
  получает запись презентации тем же изменением, что и запись в документе;
  новый контейнер работает сразу.
- Действие — либо builtin из закрытого union (`UiActionIdSchema`, для
  wire-операций — член реестра Product Wire), либо декларативный
  `custom.<владелец>.<имя>` без authority (см. рецепт 3). Опечатка во
  builtin-идентификаторе отклоняется материалайзером
  (`unknown chat action id`).
- Хук `slot:` носят только корни поверхностей (`chat-header`, `chat-composer`,
  `chat-viewport`) — это контракт Theme SDK, его не переименовывают.

### Приоритет: что затеняет что (правь ТУДА, а не сюда)

Для одного узла оба источника могут объявить одно и то же свойство. Победитель
— всегда документ; правка затенённого места **видимого эффекта не имеет**:

| Свойство                       | Правка в документе (фикстура/`ui:dev`) | Правка в Rust-таблице (`scene_chat.rs`)            |
| ------------------------------ | -------------------------------------- | -------------------------------------------------- |
| `label` (текст/aria)           | **выигрывает**                         | затенено для узлов с `label` в документе           |
| `icon`                         | **выигрывает**                         | затенено для узлов с `icon` в документе            |
| `styleRefs`                    | **выигрывает каскадом** (дописывается после inline) | работает только там, где документ не объявлял |
| классы/геометрия контейнеров   | схемой не выражаются                   | **единственный источник** (`container_look`, `button_style`, `v1/chat.rs` hooks) |
| строки сообщений, проценты     | схемой не выражаются                   | **единственный источник** (`message_action_button`, `context_meter_label`) |

В канонической фикстуре `label`/`icon` объявлены для шести кнопок
(`composer-settings`, `composer-reset`, `utility-settings`,
`utility-scroll-latest`, `utility-wand`, `composer-send`): для них правки
`button_look` по aria/icon не дают эффекта. При затенении рендер печатает
однократное уведомление в stderr (`document … shadows the built-in table`),
закреплено тестом `shadow_notice_fires_once_per_node_and_property`.

## React developer quickstart

Знакомые понятия → местные:

| В React                    | Здесь                                                                         |
| -------------------------- | ----------------------------------------------------------------------------- |
| Компонент                  | Узел документа: `nodeId` + `component` + `recipe`                             |
| Props / обработчик onClick | `actions: [{ id, parameter? }]` из закрытого реестра                          |
| Текст кнопки / i18n `t()`  | `"label": { "text": "…", "i18nKey": "chat.send" }`                            |
| `<Icon name="…"/>`         | `"icon": "PaperPlaneRight"` (реестр `UI_ICON_IDS`)                            |
| CSS-in-JS / style prop     | `"styleRefs": [{ "property", "token": "var(--…)" }]` — только токены          |
| Классы дизайн-системы      | Таблицы презентации по `nodeId` (`scene_chat.rs`) — правка кода, не документа |
| Storybook                  | `pnpm ui:dev` (живой кадр) + `pnpm blueprint-preview` (отчёт с картой хуков)  |
| Линтер/типы                | `pnpm blueprint:validate` + JSON Schema в редакторе                           |
| Тесты визуала              | парити-тест скелета + `pnpm chat:golden:check`                                |

### Рецепт 1 — переименовать кнопку и сменить иконку

Правьте документ (кнопки композера уже авторятся данными):

```jsonc
{
  "nodeId": "composer-send",
  "label": { "text": "Отправить", "i18nKey": "chat.send" },
  "icon": "PaperPlaneRight",
}
```

Сохраните — кадр обновится сам; добавьте ключ в `packages/i18n` (en+ru),
если нового `i18nKey` ещё нет.

### Рецепт 2 — перекрасить элемент токеном

```jsonc
"styleRefs": [{ "property": "background-color", "token": "var(--nt-accent-strong)" }]
```

Сырые значения (`#fff`, `12px`) схема отвергает — цвет меняется через
дизайн-токены темы, а не хардкодом.

### Рецепт 3 — добавить блок или интерактивный узел

Контейнер работает сразу: добавьте узел с уникальным `nodeId`, он пройдёт
как generic-flow. Для _интерактивного_ узла назначьте существующее действие
(`actions[0].id`) и добавьте запись презентации по `nodeId` в
`scene_chat.rs` тем же изменением.

**Новое декларативное действие — без ядра и без регенерации.** Придумайте
имя `custom.<владелец>.<имя>` (нижний регистр) и привяжите к узлу:

```jsonc
"actions": [{
  "id": "custom.acme.pin-chat",
  "params": [{ "key": "target", "value": "sidebar" }]
}]
```

Тап доезжает до хостов как `TapIntent::Custom`; поведение по умолчанию —
честный тост `[custom] …` (действия `custom.*` не имеют Product Wire
authority по контракту). Подключение реального обработчика — одна точка:
хост-арм → метод сессии; реестр плагинов появится вместе с Plugin SDK.

**Новый builtin-интен** (нужен только для wire-операций или типизированного
пейлоада): id в union `UiActionIdSchema` → кодген-декодер → вариант
`UiActionV1` + arm'ы в `v1/chat.rs`, `scene_chat.rs::data_action_attr`,
`hit_rects.rs` и хостах. Чеклист живёт в этом абзаце, пока генерация клея
не собрана в один скрипт.

## Границы (честные)

- **Динамический inline-стиль: сначала без ключа, проверяй пробой;
  высокочастотные значения — только без ключа.** В этом билде Blitz часть
  state-зависимых inline-стилей на переиспользуемых узлах застывает на первом
  нарисованном значении (волна B: слайдер-заливка, поиск чатов, фокус-рамки
  сэмплеров — лечится `key:` от того же состояния). Но НЕ все: скролл-марджин
  панели (`margin-top:-{offset}px`) применяется на reused-узле напрямую —
  проверено численными пробами (сдвиг списка карточек/вьюера/редактора на
  точное смещение). Практическое правило: (а) редко меняющееся состояние
  (`-{state}`, `-{enabled}`, `-{pct}`) — key-flip допустим и уже применён в
  коде (rail-кнопки и табы, заливка слайдера, переключатели, карточки
  плагинов, поиск чатов); (б) меняющееся на каждый пиксель/тик
  (скролл-офсеты) — ключ ЗАПРЕЩЁН: keyed-замена большого поддерева на каждый
  шаг — это чурн DOM-едитов и ловушка «invalid key» в мутаторе
  dioxus-native-dom (blitz-dom `node_at_path` по мёртвому узлу; реальная
  паника процесса). Также учти: правила классов бьют inline в этом билде
  Blitz (см. комментарий composer-actions в `product_shell.rs`), а не-auto
  `z-index` поднимает поддерево в stacking-context и не возвращает при
  relayout — z-index header/composer держать auto.
- Компактный режим (≤240 px высоты) рендерится из документа и закреплён
  золотой строкой 900×220. Overlay/nested — только M0 perf-probe сценарии
  (не product UI): активный blueprint-источник уводит их в легаси кадровым
  фоллбеком с однократным stderr-уведомлением (ADR-0056).
- Error-баннер рисует обёртка вокруг композера вне документа.
- Сломанный/чужой документ не роняет чат: включается легаси-фоллбек, а тесты
  `rejects_a_foreign_surface_document` /
  `rejects_an_unexpected_responsive_layout` фиксируют отказ на уровне сцены.
- Парити-гейт `blueprint_chrome_skeleton_matches_legacy_rsx` требует полного
  совпадения скелета с легаси; если ваша правка меняет канонический документ,
  она обязана сопровождаться такой же правкой легаси-RSX (или осознанным
  обновлением обоих), пока blueprint остаётся экспериментальным флагом.

### Интерактивные состояния: карта покрытия и React-токены (G3)

Все состояния рендерит только легаси-RSX (`lib.rs`); blueprint-хром их не
покрывает (`warn_uncovered_variant`), поэтому гейт их не сравнивает. Паритет —
внешний, против React-компонентов в `apps/web/src/components/`:

| Состояние | React-эталон | Поведение натива |
|---|---|---|
| Меню снапшотов | `ChatSnapshotsMenu` | строки `open-snapshot` (чат-id в key) → `ShellAction::OpenSnapshot`; закрытие: тап вне панели, тогл триггера |
| Variant picker | `MessageVariantPicker` | строки `swipe-pick` (variant-id в `data-ui-key`, владелец = открытый пикер) → `ShellAction::PickVariant`; активный ряд (`active-`) только закрывает; закрытие: тап вне, тогл триггера |
| Инлайн-редактор | `MessageBubble` `.editor` | Save отключён на пустом черновике (opacity .45) |
| История ревизий | `MessageRevisionHistoryCard` | токены диалога; Restore/Load-more из React НЕ перевезены (честный пробел) |
| Карточка деталей | `MessageDetailsCardV2` | 3 режима (details/actions/edit); danger-зона без рамочного бокса |
| Поиск в шапке | `ChatWorkspace` `.chatSearch` | бескаркасный прозрачный инпут 36px |

Токены — из `packages/ui/src/styles/tokens.css` (тёмный лист):
диалог/поповер = `surface-overlay #292522`, бордер `#39342f` (1px), радиус
`overlay 20px` (диалоги) / `control 10px` (поповеры), тень
`0 24px 64px rgba(0,0,0,.58)`, ширина `min(560px, 100%−16px)` по центру
(диалоги), padding 24; вторичные поверхности `#24211e`; hover инверсией 7–10%
(`rgba(33,27,23,α)`), active-вариант `accent-soft #492a20`, danger `#b23b35`.
Клавиша Escape НЕ закрывает оверлеи (клавиатурный контур хоста пока не ведёт
оверлеи) — закрывайте тапом вне панели или триггером.

## Мини-пример: убрать группу utilities и переименовать Send

```jsonc
// ui-blueprint-document-chat-v1.json → composer-actions.children
// 1) удалить узел "composer-utilities" целиком;
// 2) презентация кнопки — правка только данных:
{
  "nodeId": "composer-send",
  "label": { "text": "Отправить", "i18nKey": "chat.send" },
  "icon": "PaperPlaneRight",
  "styleRefs": [{ "property": "background-color", "token": "var(--nt-accent-strong)" }],
}
```

После правки: `--blueprint`-кадр рисует композер без левого ряда иконок,
Send получает новый текст/стиль; `document_structure_drives_the_scene` в
`crates/presentation-blueprint/tests/chat.rs` демонстрирует ту же механику
на тестах (удаление `composer-context`, добавление неизвестного узла), а
`authored_presentation_overrides_flow_into_the_scene` — перенос лейбла,
иконки и styleRefs из JSON в сцену. Пиксельное доказательство: правка
лейбла+иконки меняет снапшот относительно goldens, при канонических
значениях diff остаётся 0.0000%.
