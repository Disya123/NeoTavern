# Аудит image-пайплайна нативного рендера (2026-09-05)

Корневой разбор жалоб «изображения постоянно поверх всего» и «странно
масштабируются». Документ фиксирует факты с координатами, причину каждого
симптома и поэтапный план исправления. Это аудит, не changelog: код не менялся.

## 1. Карта: пять отдельных image-путей

Изображения в нативном пайплайне существуют в пяти несвязанных подсистемах:

| #   | Путь                                                                                        | Файлы                                                                                                                                                      | Статус                                                                 |
| --- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1   | **AvatarGpu overlay** — аватары (header 32/44, message 36, card 48, editor 64, gallery 4:5) | `presentation-chat/src/avatar.rs`, `avatar_gpu.rs`, `presentation-m0-d2/src/layout_probe.rs`, `vello_gpu.rs::composite_avatars`, Android `overlay_avatars` | живой, основной                                                        |
| 2   | **Wallpaper blit underlay** — фото-обои десктопа                                            | `bin/neocompositor-desktop.rs` (+ `vello_gpu.rs::upload_wallpaper`/`set_wallpaper_rect`, blit-шейдер rows 2/3)                                             | blit-шейдер подложка (этап C), desktop-only (`--wallpaper`)            |
| 3   | **In-scene Blitz `<img>`** — любые `asset:{id}`/`data:` URI в DOM                           | `presentation-m0-d2/src/asset_net.rs` (LocalNetProvider), `vello_sink.rs::brush_ref`                                                                       | **возвращён (этап B)**: растровые URI рисуются через vello image atlas |
| 4   | **Markdown message-image**                                                                  | `presentation-dioxus-shell/src/markdown.rs:615-621`                                                                                                        | заглушка 32px без контента                                             |
| 5   | **Wallpaper div'ы сцены**                                                                   | `product_shell.rs:2858-2867` (`chat-wallpaper` transparent + `chat-wallpaper-overlay` rgba)                                                                | живой (dim-слой)                                                       |

Путь №3 — архитектурно правильный (картинка часть сцены: clip, opacity,
z-order работают сами). Он был выключен (`vello_sink.rs:220-223`,
Vello 0.9 Android Vulkan чёрный SurfaceView) и **возвращён в этапе B**:
`brush_ref` снова кодирует `Paint::Image` в vello (persistent image atlas),
`<img src="asset:{id}">` резолвится `LocalNetProvider` из процесса-хранилища
миниатюр.

## 2. Симптомы → причины

### «Постоянно поверх всего»

| Проявление                                             | Причина                                                                                                                      | Координата                |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| Аватары поверх модалок/панелей/тостов/дропдаунов       | Оверлей — отдельный render pass поверх готового кадра (`LoadOp::Load`), без знания о z-order, клипах и модальных слоях сцены | `avatar_gpu.rs:447-473`   |
| Аватары поверх даже если список нарисован «до»         | В display list они и так аппендятся в конец (`ops.extend`) — тупиковый z                                                     | `layout_probe.rs:104-105` |
| Геометрия аватаров не совпадает со сценой при оверлеях | dest-ректы берутся из layout-прогона последнего produce («This walk is not paint order»), а не из paint-порядка сцены        | `layout_probe.rs:4`       |

### Сопутствующие дефекты той же семьи

- **Обои съезжают при скролле и рвутся по границе бэнда**: фото композитится в
  `resolve` (full-window) **до** blit-скролла → пиксели фото внутри бэнда едут
  вместе с контентом, выше/ниже бэнда — нет; в React фон фиксирован
  (photo внутри workspace, не под сайдбаром). Натив же рисует full-window dest —
  фото подсвечивается сквозь стекло сайдбара. `neocompositor-desktop.rs:491-501`.
- **Двойной рендер слота**: сцена красит letter-фолбэк, оверлей кладёт битмап
  поверх; до готовности текстуры виден фолбэк, потом «поп» — и расхождение
  геометрии фолбэка/битмапа никуда не девается.
- **`AVATAR_OVERLAY`-ветка Android мертва**: `AVATAR_OVERLAY.store(true)` не
  вызывает никто — `composite_avatar_overlay` недостижим. Либо доназначить,
  либо удалить. `android_surface.rs:201,1822-1842`.
- **Markdown-картинки не существуют**: `Inline::Image` → серый брус 32px
  (`markdown.rs:615-621`); `ProductPaintLayout.markdown_image_blocks` их считает,
  рендер нет.
- **Тяга оригиналов**: `assets.content` отдаёт исходные байты (Hazel 2.2 MiB
  base64) ради 192²-миниатюры; `hydrate_character_avatars` фетчит по 50
  (PAGE_LIMIT) на каждый refresh — на больших библиотеках дорого. Декод-лимиты
  при этом корректные (`avatar.rs:24-26`).

## 3. Корневые причины (по ранжированию)

1. **Изображения не first-class в display list.** In-scene Image brush
   отключён из-за бага Vello 0.9 на Android Vulkan → вся живая ветка —
   параллельный overlay с собственной координатной системой, собственным
   клипом и пост-проходом поверх кадра. Из этого выводятся ВСЕ симптомы
   «поверх всего» и большая часть зет-проблем.
2. **Один пресет текстуры (192² квадрат) на все слоты.** Нет cover-fit под
   dest, нет mipmaps, нет слот-специфичных размеров → растяжения, апскейлы,
   алиасинг.
3. **Захардкоженные токены** (радиус 10, размеры слотов) → круг/квадрат
   рассинхрон, дрейф от темы и React golden.
4. **Обои**: full-window dest + запекание в raster до blit-скролла → съезжают,
   рвутся, светятся под сайдбаром.
5. **Контентные картинки сообщений** — фича отсутствует (заглушка), тот же
   корень №1.

## 4. Что сделано правильно (сохранить)

- CPU/GPU кэши миниатюр: LRU, байтовые бюджеты (8 MiB / 64 записи), эвикция
  по давлению, device-epoch инвалидация (`session.rs:78-82`, `avatar_gpu.rs:15-17`).
- Decode-preflight без аллокаций: лимиты размера файла/осей/пикселей
  (`avatar.rs:46-65`).
- Premultiplied alpha по всему пути; destination-over для обоев — верная
  семантика «фото под стеклом».
- Контентно-адресные asset id в ядре (sha256-дедуп) — смена аватара = новый id,
  stale-инвалидация на уровне id отсутствует. `runtime-kernel/src/assets.rs:82-99`.
- Никаких `data:` URI в Dioxus-дереве для аватаров (осознанное решение,
  правильное по памяти/перфу).

## 5. План исправления (этапы)

### Этап A — «остановить кровотечение» (малый срез, без смены архитектуры) — ВЫПОЛНЕН 2026-09-05

1. ✅ **Cover-fit в шейдере оверлея**: UV-подвыборка центра текстуры под аспект
   dest-ректа (квадратная текстура → прямоугольный слот кропится, а не
   растягивается). Чинит галерею 4:5 и все будущие непропорциональные слоты
   без перегенерации текстур; обои с совпадающим аспектом — identity.
   `avatar_gpu.rs` AVATAR_WGSL + `tex_aspect` в uniform.
2. ✅ **Радиус клипа из данных слота**: `data-avatar-radius` рядом с
   `data-avatar-asset` из того же источника, что и `border-radius` фолбэка
   (scene_chat: 16/18 круги; product_shell: `--st-radius-control` = 10);
   `AvatarSlot.radius_css`, дефолт для сторонних слотов — прежние 10.
3. ✅ **Pixel-snap dest**: `round(css * scale)` к целым физическим px.
4. ✅ **Мипмапы**: полная mip-цепочка строится на CPU при upload
   (премультиплицированный даунсэмпл линеен; wgpu 29 не имеет
   `generate_mipmaps`) + `MipmapFilterMode::Linear`.
5. ✅ Удалена мёртвая `AVATAR_OVERLAY`-ветка (static + JNI else-if +
   `composite_avatar_overlay`).

Верификация: дифф против прежнего кадра локализован в аватарных зонах
(10 676 px из 836 000, кластеры = слоты сайдбара + шапка), остальное
бит-в-бит; шапка чата визуально круг (был скруглённый квадрат); mid-flight
сдвиг с обоями 525 px шума из 286 624, header/composer 0 diff, филлер
#151311; тесты m0-d2/chat/shell/session зелёные; `aarch64-linux-android`
зелёный.

### Этап B — честный пайплайн (архитектурный корень) — ВЫПОЛНЕН 2026-09-05

6. ✅ **In-scene Image brush возвращён.** Репро-тест
   (`vello_gpu::tests::gpu_vello_image_brush_rasterizes_on_the_sampled_target`)
   доказал: vello 0.9 (vendored) растеризует `Brush::Image` через persistent
   image atlas корректно на desktop GPU (Vulkan), в sampled-таргет попадают
   пиксели картинки. `brush_ref` снова отдаёт `Paint::Image → Brush::Image`;
   историческая апликатура «чёрный SurfaceView» осталась только на
   неподтверждённых Android-устройствах — на этот случай есть escape-hatch
   `NEOTA_INSCENE_IMAGES=0` (см. риски).
7. ✅ **Аватары переведены в сцену.** Механизм: `<img src="asset:{id}">` в
   аватарных слотах (шапка 32, сообщение 36, карточка/редактор/галерея в
   `product_shell`); `asset:{id}` резолвит `LocalNetProvider`
   (`presentation-m0-d2/src/asset_net.rs`) из процесса-глобального
   LRU-хранилища (`AssetStore`: 64 записи / 32 MiB, пополнение при гидрации
   `insert_avatar_thumb` → PNG-кодирование `display_png_from_thumb`). Blitz
   рисует `<img>` в paint-порядке с полным object-fit и клипом по
   border-radius (`is_image`-клип идёт по скруглённому padding-box) —
   z-order/модалки/клипы работают сами. Рисующий GPU-оверлей отключён на
   обоих хостах (остаётся только при kill-switch); `AvatarGpu` продолжает
   обслуживать обои (desktop under-composite, этап C перенесёт). Из
   display-list метаданные `attach_image_paints` пишутся тоже только в
   fallback-режиме.
8. ✅ **Message-image.** `Inline::Image` с `asset:{id}` рендерит настоящий
   `<img>` (`object-fit: contain`, max-height 420 CSS px, radius 16);
   http(s)-ссылки сохраняют прежнюю заглушку (сети в probe нет). Гидрация:
   `asset_image_refs` (тот же парсер, что рендерит) собирает id'ы из
   загруженных страниц, `hydrate_message_assets` кладёт в стор миниатюру с
   сохранением аспекта (`message_image_thumb`: ≤768px, JPEG q82 для
   непрозрачных, PNG с альфой), вызовы — `absorb_latest_page` +
   `note_durable`, лимит 32 фетча за проход, дедуп по стору.
   Демо-данные чинены: `asset:thumb-N` нарушал контракт
   `assets.content` (`assetId` = UUID) → фото-сообщения fake wire теперь
   ссылаются на детерминированные UUID (`wire_id(0x9000+n)`).
9. ✅ Слот-специфичные размеры сделаны через wire-параметр (этап C): аватары
   запрашивают `maxPx=192`, message-image — `maxPx=768` (те же эффективные
   потолки, что в этапах A/B, но теперь растит ядро). «Лестница» 96/384 не
   введена: один asset = одна запись в AssetStore/GPU-кэше, пер-слотные
   размеры дали бы несколько фетчей одного и того же актива ради нулевой
   визуальной выгоды при текущем масштабе слотов (политика «наибольший слот
   задаёт размер»); апскейл галереи 4:5 остаётся известным ограничением.

Дополнительный фикс, вскрывшийся на e2e: оценки высот строк в
`compositor_height_index` (56px на сообщение) не покрывали фото-строку →
`debug_assert` в chat-viewport `present` («overscan miss must not open a
transparent gap») на 3 сообщениях. Строки с `asset:`-картинками теперь
оцениваются как `56 + 436` CSS px (завышение безопасно: overscan-окно
перекрывает реал).

Верификация: GPU-репро зелёный (пиксель = цвет картинки); desktop e2e
снапшоты (`neocompositor-desktop --snapshot`): фото-сообщение рисуется
в сцене (~270×420, radius 16, аспект сохранён), аватары шапки/сообщений/
карточек — реальные растры при отключённом оверлее; blueprint-parity
(95/95 compositor_host, включая обновлённый контракт
`raster_images > 0` вместо старого «letter fallback only»); m0-d2/shell/
session/neocompositor зелёные; `aarch64-linux-android` check зелёный
(полный тест-ран на устройстве требует NDK — здесь недоступен).

Известные следствия:

- Декод картинки в DOM-кэше blitz — на каждый produce (документ
  пересобирается); thumbnail-размеры удерживают стоимость в миллисекундах.
  Постоянный кэш декодов между produce — кандидат в этап C вместе с
  переходом на kernel-миниатюры.
- До гидрации (первый кадр после смены чата) фото-блок имеет нулевую
  высоту (нет intrinsic size) и появляется после следующего produce —
  стандартное CLS-поведение `<img>`.
- SVG в `<img>` по-прежнему не разрешён (usvg-чёрный-экран эпоха);
  `LocalNetProvider` обслуживает только растровые data: URI и `asset:`.

### Этап C — обои и полировка — ВЫПОЛНЕН 2026-09-06

10. ✅ **Обои вне blit-сдвига.** Фото композитится в самом blit-шейдере как
    фиксированная подложка: сэмплируется по НЕсдвинутому uv внутри dest-ректа
    с премультиплицированным under-composite (`rgb = c.rgb + wall·(1−c.a)`),
    регион бэнда с вышедшим за диапазон источником показывает фото поверх
    плоского филлера вместо замены («плоская полоса над фото» устранена).
    Дим-градиент перенесён в шейдер (`scroll[3].y`) — фиксирован вместе с
    фото, как gradient внутри React-`.wallpaper`; сценовый див
    `chat-wallpaper-overlay` в wallpaper-режиме прозрачен (скелет-хук
    остаётся). dest — рект `part:chat-wallpaper` из slot-скелета: оба дива
    перенесены внутрь `main#chat-workspace` (position:relative,
    overflow:hidden) с React-bleed `−12px` (`--st-space-md`), так что фото
    больше не светится сквозь стекло сайдбара. Uniform расширен 32→64 байта
    (строки 2/3: рект в uv + enable + dim), биндинги 3/4 (текстура+сэмплер;
    без обоев биндится прозрачный 1×1 dummy); shader/uniform байт-в-байт
    одинаковы у desktop и Android (Android держит rows 2/3 нулями). Удалён
    resolve-side `composite_wallpaper_under`/`AvatarGpu::blit_under`
    (destination-over до blit) вместе с `pipeline_under` и константой
    `WALLPAPER_ASSET_ID`. Обои не перезаливаются на каждом produce: ключ
    контента (epoch) + рект обновляются отдельно
    (`upload_wallpaper`/`set_wallpaper_rect`).
11. ✅ **Токенизация.** `ThemeTokens` дополнен size-токенами из Theme SDK
    (`control-height{,-large,-sm,-xs,-2xs}`, `space-{sm,md,xl}`; размеры
    темо-независимы — `DEFAULT_DARK_TOKENS` расширяет light-набор) + парсинг
    манифеста + `*_px`-хелперы с fallback. Слоты рендерятся из токенов:
    шапка чата = `control-height-2xs` (32), сообщение = `control-height-xs`
    (36), карточка = `control-height-large` (**52** — прежний инлайн 48 был
    расхождением с React `.cardAvatar`), редактор =
    `calc(large + space-md)` (64), панельный header = `control-height` (44),
    радиусы кругов = size/2, некруглые = `radius-control`;
    `data-avatar-radius` считается из тех же чисел. viewerAvatar приведён к
    React-паритету (`object-fit: contain`, `radius-control`, 1px
    border-strong; раньше — 48px square cover). Обновлён устаревший golden
    shell-теста («48px, not 52px» → токен-семантика).
12. ✅ **Тяга оригиналов.** Новый wire-op `assets.thumb`
    (`{assetId: UUID, maxPx: 16..1024}` → `{format: jpeg|png, width, height,
contentBase64}`, лимит ответа 3 MiB; WIRE_SCHEMA_HASH обновлён).
    Ядро: декод с жёстким preflight (оригинал ≤64 MiB, оси ≤16384 px,
    ≤64 MP; больше — стабильный ContractViolation), aspect-сохраняющий
    `thumbnail(maxPx)`, JPEG q82 для непрозрачных / PNG с альфой, диск-кэш
    `<data-root>/cache/thumbnails/{sha256}-{maxPx}-v{ALGO}.{ext}` (§12:
    ключ = хэш+размер+версия, атомарная запись temp+rename, кэш удаляем и
    пересобираем; оригиналы не трогаются). Session-гидрация (аватары 192,
    message-image 768) переведена на `assets.thumb`: 2.2 MiB base64
    оригиналов по проводу больше не ходят ни для аватаров, ни для фото в
    сообщениях (ранее `assets.content` возвращал оригинал ради 192²).
    Клиентские `premultiplied_cover_thumbnail` (cover-кроп) и
    `message_image_thumb` удалены; `AvatarThumb` строится без cover-кропа —
    display-пути (cover-fit шейдер этапа A / in-scene object-fit) сами
    подгоняют кадрирование. FakeWire отражает реальные семантики
    `assets.thumb`, так что demo-пайплайн тоже не гоняет оригиналы.

## 6. Известные риски плана

- Этап B зависит от воспроизводимости vello-бага: если Image brush в текущем
  дереве зависимостей всё ещё красит SurfaceView в чёрный на Android — атлас
  обязателен; если нет — прямой путь.
  **Статус после этапа B**: на desktop GPU атлас корректен (репро-тест);
  Android-устройство в этой среде недоступно — первое включение на устройстве
  проверять по скриншоту. Escape-hatch: `NEOTA_INSCENE_IMAGES=0` возвращает
  отключение Image-брашей в `brush_ref` **и** рисующий GPU-оверлей аватаров
  на обоих хостах (ветка Stage A), так что деградация ограничена «письма
  вместо фото», а не чёрным экраном; катастрофический случай целиком ловит
  существующий CPU-raster fallback диагностик Android-хоста.
- Этап C.10 выполнен: фото больше не в замороженном растре resolve, а в
  blit-шейдере; пиксельные пробы этапов 2–3 (филлер #151311) в wallpaper-режиме
  сменились фото-семантикой (см. «Верификация этапа C»). Без обоев шейдер
  бит-в-бит совпадает с прежним blit (филлер #151311 сохранён).
