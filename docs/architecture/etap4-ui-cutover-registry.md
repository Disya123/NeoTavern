# Этап 4 — UI/API cutover registry (working checklist)

> **Status.** Living working document for the ADR-0038 Этап-4 program on the
> `react-primary` branch: the vertical-slice registry that moves every
> production React call off `/api/v2` onto the Product Wire / Kernel plane,
> in the ТЗ §20 order, one slice per PR-sized change. Exit criteria (ТЗ
> §20 Этап 4): a repository scan finds **zero** production `/api/v2` or
> `legacyRaw()` calls, and legacy Fastify no longer owns product data.
> The ST-plugin compatibility layer is already gone (ADR-0059 Amendment 1,
> 2026-10-31); what remains legacy is the Fastify/Drizzle contour itself and
> SillyTavern data import.

## 1. Slice protocol (Definition of Done per row)

Every slice follows the vertical order mandated by ТЗ §20 Этап 4:

1. **contract** — wire op(s) in `packages/contracts/src/wire/registry.ts`
   (schema, scope, idempotency, byte limits, error codes); codegen refreshed;
2. **application** — kernel handler + storage, component + integration
   tests, payload gates where the op is heavy;
3. **adapter** — host surfaces (headless remote-http) reachable; no silent
   fallbacks;
4. **UI** — `apps/web` switches to the wire path (kernel mode), legacy
   browser/sidecar mode either removed or explicitly dual-mode with an
   honest default;
5. **E2E** — Playwright path for the migrated journey (kernel mode first;
   the legacy-config quarantine only while the sidecar contour exists);
6. **remove the legacy route** — the Fastify route module row is deleted in
   the SAME slice; `docs/architecture/operations-inventory.md` and the
   `ui-legacy-surface` baseline are regenerated.

A slice may ship steps 1–5 and defer step 6 only when another panel still
shares the route; the shared route's last consumer owns its deletion.

## 4. Blocked on the ingestion transport (decision pending)

Two clusters cannot be honestly ported before the wire grows a large-file
ingestion contract. Both are blocked by the same fact: wire requests are JSON
(and `assets.put`, the only byte-carrying op, admits **1 MiB**), while the
kernel is a synchronous single writer.

| Cluster | Payload                                                | Why the wire cannot carry it today                                                                      |
| ------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 8 tail  | TTS audio / generated images / transcription uploads   | binary or multipart; multi-MB base64 results would blow DTO budgets                                     |
| 10      | SillyTavern backups (`/imports/sillytavern/*`)         | multipart archive up to the legacy **4 GiB** cap; extraction is minutes                                 |
| 13      | Chat background wallpapers (`/backgrounds/*`)          | multipart upload up to the legacy **25 MiB** cap; original serving above the 4 MiB `assets.content` cap |
| 21a     | Plugin blobs (`/plugins/:id/blobs*`)                   | binary bodies with an 8 MiB per-blob legacy cap; the sandbox streams them through the host session      |
| 20      | Plugin sandbox/assets (`:id/sandbox*`, `:id/assets/*`) | whole package files served to the iframe; the wire has no "raw file bytes" body type                    |

Candidate contracts (owner decision required — no ADR is recorded yet, and
neither is implemented):

1. **Host-staged path.** The host (desktop Tauri / headless server) streams the
   file into the data root itself and calls a wire op with a staged-upload id
   or a relative path. Small wire surface, no kernel streaming; the remote Web
   Client needs the host's own HTTP upload endpoint (outside Product Wire).
2. **Chunked upload ops.** `assets.upload.begin/append/finish` with bounded
   chunks (≤1 MiB each), assembling under the asset plane with a TTL and
   explicit cancellation. Works for every client uniformly and keeps Product
   Wire canonical, but adds a mutable staged-upload resource the kernel must
   own, clean up and bound.

Until then the honest state is what ships today: the React hooks refuse in
kernel mode with a stable `UnsupportedError`, and the legacy sidecar keeps the
feature.
